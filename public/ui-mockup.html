แสดงผลและเลือกเป็นปี พ.ศ. สบายตา ไม่ทำให้ผู้ใช้สับสนเรื่องปี ขณะที่ระบบจัดเก็บเป็น ค.ศ. (ISO-8601) อัตโนมัติทางเบื้องหลัง

3. Single Error Focus

หากกรอกผิดหลายจุด ระบบจะนำเฉพาะข้อผิดพลาดแรกสุดขึ้นมาแสดงพร้อม Auto-scroll & Focus ลด Cognitive Overload

เปรียบเทียบแนวทางสถาปัตยกรรม Left Menu (Architecture Options)

แนะนำสูงสุด (Recommended)

แนวทางที่ 1: Dynamic Role-Scoped Sidebar

เมนูด้านซ้ายจะเปลี่ยนชุดตามบทบาทหน้าที่ของ User ที่ล็อกอิน หรือสลับระบบได้จาก Header

ข้อดี (Pros):
  • ลดความสับสนอย่างเด็ดขาด: เจ้าหน้าที่แต่ละฝ่าย (เช่น การเงิน, ช่างประปา, พัสดุ) จะเห็นเฉพาะงานที่ตนเองต้องรับผิดชอบ
  • พื้นที่แนวตั้งไม่อึดอัด: เมนูสั้น กระชับ ตัวหนังสือใหญ่ 16px มองเห็นง่าย เหมาะกับเจ้าหน้าที่ 40+ ปี
  • รักษาความปลอดภัย (Least Privilege): ผู้ใช้ทั่วไปไม่มีเมนูหลังบ้านหลุดมารกสายตา
เหมาะสำหรับ:
งานบริหารเทศบาลที่มีแผนกและหน้าที่รับผิดชอบชัดเจน

แนวทางที่ 2: Unified Mega Sidebar (Tree Accordion)

รวมทุกระบบไว้ในแถบเดียว โดยใช้ระบบ Collapse / Expand แยกตามโมดูล

ข้อดี / ข้อสังเกต:
  • เห็นภาพรวมทุกระบบงานได้จากที่เดียวสำหรับ Super Admin
  • ข้อเสีย: รายการเมนูยาวเกินไป (Vertical Overload) ผู้ใช้สูงอายุต้อง Scroll หาเมนูยาก และมักคลิกผิดพลาด
เหมาะสำหรับ:
ระบบขนาดเล็กที่มีเมนูไม่เกิน 8-10 รายการ
ข้อเสนอแนะในการ Implementation:

ใช้ **AdminLTE 4 Menu Filter (`RoleMenuFilter.php`)** ร่วมกับ Spatie Permission ในการกรองอาเรย์เมนูจาก `config/adminlte.php` โดยอัตโนมัติ ทำให้ไม่ต้องแยกไฟล์ Layout กระจัดกระจาย ทุกหน้าจะใช้มาตรฐานเดียวกันผ่าน `@extends('adminlte::page')`
