# ADR 0006: ระบบ Dynamic Left Menu ตามสิทธิ์บทบาทผู้ใช้งาน (Role-Based Sidebar) และแบบฟอร์มมาตรฐาน Senior-Friendly

## Status
Accepted (วันที่ 2026-11-01)

## Context
ระบบบริหารจัดการเทศบาลดิจิทัล OTP 2025 มีผู้ใช้งานหลักคือเจ้าหน้าที่ท้องถิ่นและประชาชนที่มีอายุ 40 ปีขึ้นไป ในสถาปัตยกรรมเดิมระบบประสบปัญหาสำคัญ 2 ประการ:
1. **Left Sidebar แตกกระจายและรายการเมนูยาวเกินไป:** แต่ละระบบย่อย (เช่น Super Admin, ขยะ, พัสดุ, สวัสดิการ) มีไฟล์นำทางของตนเอง (`*_navigation.blade.php`) หรือเมนูใน AdminLTE แสดงผลปะปนกันทุกฝ่าย ทำให้เจ้าหน้าที่เฉพาะทาง (เช่น ช่างประปา, การเงิน) ต้องมองผ่านเมนูที่ไม่เกี่ยวข้องจำนวนมาก เกิดความสับสนในการใช้งาน
2. **ฟอร์มการใช้งานยังขาด Visual Hierarchy และความน่าใช้งาน:** ฟอร์มหลายหน้ามีช่องกรอกจำนวนมากวางเรียงกันโดยไม่มีการแบ่งขั้นตอน (Step Wizard), ขาดการแนะนำข้อมูลที่เข้าใจง่ายสำหรับผู้สูงวัย, และการจัดการข้อผิดพลาดเมื่อกรอกผิดยังแสดงพร้อมกันหลายรายการหรือยังใช้ Technical Exception ซึ่งสร้างความวิตกกังวลแก่ผู้ใช้

## Decision
เราตัดสินใจวางสถาปัตยกรรมเมนูด้านซ้ายและฟอร์มมาตรฐานใหม่ดังนี้:
1. **Dynamic Role-Based Menu Architecture:** ใช้ Event Listener `BuildingMenu` ของ AdminLTE 4 ร่วมกับ `App\Services\Navigation\RoleMenuService` เพื่อตรวจสอบ Spatie Roles (`Super Admin`, `Admin`, `finance`, `tabwater`, `keptkaya`, `inventory`, `staff`, `User`) ของผู้ใช้งานขณะ Runtime และประกอบรายการเมนูด้านซ้ายเฉพาะโมดูลที่ผู้ใช้นั้นมีหน้าที่รับผิดชอบจริงเท่านั้น
2. **Global Hub Quick Access:** ทุกชุดเมนูด้านซ้ายต้องมีปุ่มทางลัด "ศูนย์รวมระบบงาน (Hub)" ด้านบนสุดเสมอ เพื่อให้ผู้ใช้สามารถคลิกสลับไปยังโมดูลอื่นได้อย่างสะดวกรวดเร็ว
3. **Senior-Friendly Form Components:** สร้างชุด Blade Components มาตรฐาน (`resources/views/components/form/`) ครอบคลุม:
   - Touch Target สำหรับ Input และปุ่ม Action ความสูงขั้นต่ำ 48px–52px (ADR 0003 & 0005)
   - Step Wizard Indicator สำหรับฟอร์มที่มีข้อมูลซับซ้อน เพื่อแบ่งขั้นตอนการกรอกทีละส่วน
   - Thai Buddhist Era Datepicker (พ.ศ.) แบบ Dual-Binding แปลงเก็บเป็น ค.ศ. `YYYY-MM-DD` เบื้องหลัง
   - Single-Error Focus Banner กรองแสดงเฉพาะข้อผิดพลาดแรกสุด พร้อม Auto-scroll และ Auto-focus
   - Action Bar มาตรฐาน: ปุ่ม "ยกเลิก/ล้างค่า" อยู่ฝั่งซ้าย และปุ่ม "บันทึกข้อมูล" อยู่ฝั่งขวา

## Consequences
- **Positive:** เมนูด้านซ้ายมีความกระชับ ตัวอักษรและไอคอนใหญ่ 16px สบายตา ผู้ใช้งานแต่ละแผนกมองเห็นเฉพาะงานที่ตนเองต้องรับผิดชอบ ลดความผิดพลาดในการคลิกเมนูผิด ฟอร์มการใช้งานมีความทันสมัย น่าใช้งาน และเป็นมิตรกับผู้สูงอายุ 40+ ปี
- **Negative:** นักพัฒนาต้องลงทะเบียน Route และ Permission ลงใน `RoleMenuService` ให้ถูกต้อง และต้องปรับหน้าฟอร์มเดิมให้สืบทอดจาก Blade Components มาตรฐาน
- **Constraints (สำหรับ AI Agent):**
  - เมนูด้านซ้ายต้องผ่านการกรองสิทธิ์ด้วย Spatie Permission เสมอ ห้ามฮาร์ดโค้ดแสดงทุกเมนูแก่ทุก Role
  - ต้องมีปุ่มกลับหน้าศูนย์รวมระบบงาน (`route('accessmenu')`) ปรากฏอยู่ใน Sidebar เสมอ
  - ช่องกรอกข้อมูลและปุ่มในฟอร์มทั้งหมดต้องมีความสูงขั้นต่ำ 48px–52px และมี `novalidate` บน `<form>`
  - การจัดการ Validation Error ต้องแสดงเฉพาะ Error แรกสุด (First Error Only) ห้ามแสดง Error พร้อมกันหลายรายการจนสร้าง Cognitive Overload
